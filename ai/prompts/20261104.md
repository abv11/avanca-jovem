# Planejamento técnico — HomeViewModel

## 1. Instruções

Analise o projeto Avança Jovem e elabore um planejamento técnico para adaptar exclusivamente o arquivo `HomeViewModel.kt` à utilização dos quatro estados da tela:

- Carregando;
- Vazio;
- Erro;
- Sucesso.

O projeto já possui o arquivo `UiState.kt`, com a seguinte estrutura:

- `UiState.Carregando`
- `UiState.Vazio`
- `UiState.Erro(mensagem: String)`
- `UiState.Sucesso(estudante: Estudante, metas: List<Meta>)`

Utilize essa estrutura existente exatamente como está, sem modificá-la.

Antes de elaborar o planejamento, examine a implementação atual do `HomeViewModel.kt` e compreenda como ele trabalha com o Repository, os dados do estudante e as metas.

O planejamento deve considerar:

- Utilização de `MutableStateFlow` privado e `StateFlow` público.
- Inicialização do estado como `Carregando`.
- Inicialização do carregamento no bloco `init`.
- Existência de um método público `carregar()` para realizar novas tentativas.
- Retorno ao estado `Carregando` antes de cada tentativa.
- Emissão de `Vazio` quando não houver metas.
- Emissão de `Sucesso` quando houver metas, incluindo o estudante e a lista de metas.
- Tratamento de `IOException` antes de `Exception`.
- Preservação de `CancellationException`.
- Apresentação de mensagens de erro amigáveis.
- Prevenção de coletores duplicados.
- Preservação do funcionamento de `deleteMeta()` e `clearError()`.

## 3. Requisitos técnicos

O planejamento deve explicar como implementar os quatro estados exclusivamente no `HomeViewModel.kt`.

### 3.1. Estado privado e público

Planeje a utilização de:

- Um `MutableStateFlow` privado para controlar o estado da tela.
- Um `StateFlow` público para disponibilizar esse estado aos componentes que já utilizam o ViewModel.

Explique como essa estrutura permitirá acompanhar as mudanças de estado sem permitir que outros componentes alterem diretamente o fluxo.

### 3.2. Estado inicial

O estado inicial deve ser `UiState.Carregando`.

O carregamento dos dados deve ser iniciado no bloco `init`, respeitando a arquitetura existente.

### 3.3. Estado Carregando

O estado `Carregando` deve ser emitido:

- Na inicialização do carregamento.
- Antes de cada nova tentativa realizada pelo método `carregar()`.

Explique como garantir que o estado seja atualizado corretamente durante essas operações.

### 3.4. Estado Vazio

O estado `UiState.Vazio` deve ser emitido quando a consulta das metas for concluída com sucesso, mas não houver nenhuma meta disponível.

Considere a estrutura real dos dados retornados pelo Repository.

### 3.5. Estado Sucesso

O estado `UiState.Sucesso` deve ser emitido quando houver metas disponíveis.

A emissão deve incluir:

- O estudante correspondente.
- A lista de metas carregadas.

Utilize os tipos e as propriedades já existentes no projeto.

### 3.6. Estado Erro

O estado `UiState.Erro` deve ser emitido quando ocorrer uma falha durante o carregamento dos dados.

O planejamento deve considerar:

- Tratamento de `IOException` antes de `Exception`.
- Mensagens de erro compreensíveis para o usuário.
- Evitar apresentar mensagens técnicas ou detalhes internos das exceções diretamente na interface.
- Preservar o cancelamento das coroutines por meio de `CancellationException`.

Explique como o tratamento de exceções deve funcionar sem prejudicar o ciclo de vida das operações assíncronas.
