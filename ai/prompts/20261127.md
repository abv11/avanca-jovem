# Instrução

Analisar o projeto Android Avança Jovem, desenvolvido no Android Studio com Kotlin e Jetpack Compose, e elaborar um planejamento para implementar autenticação com conta Google e armazenamento dos dados individuais de cada usuário na nuvem.

O objetivo é permitir que cada usuário entre no aplicativo utilizando sua conta Google e tenha seus dados armazenados na nuvem, associados exclusivamente à sua conta, possibilitando recuperar suas informações em caso de troca de dispositivo, desinstalação do aplicativo ou impossibilidade de utilizar o celular antigo.

Atualmente, o aplicativo armazena os dados apenas localmente no dispositivo. A implementação deverá permitir a migração dos dados existentes para a nuvem, preservando as funcionalidades atuais do aplicativo.

O projeto deverá utilizar:

- Firebase Authentication para autenticação com conta Google.
- Cloud Firestore para armazenamento e recuperação dos dados dos usuários.
- Firebase Security Rules para proteger os dados de cada usuário.

Antes de elaborar o planejamento, analisar a estrutura atual do projeto, os arquivos existentes, as telas, os modelos de dados, os repositórios, os mecanismos de armazenamento local e a lógica de navegação.

O planejamento deverá ser específico para o projeto Avança Jovem, baseado na análise real dos arquivos existentes.

# Objetivos da implementação

1. Implementar uma tela de login com a opção de entrar utilizando uma conta Google.
2. Permitir que o usuário permaneça autenticado ao fechar e abrir o aplicativo novamente.
3. Identificar cada usuário por meio do UID fornecido pelo Firebase Authentication.
4. Criar uma estrutura no Cloud Firestore para armazenar os dados de cada usuário separadamente.
5. Garantir que todas as informações criadas ou modificadas pelo usuário sejam associadas ao UID da sua conta.
6. Recuperar os dados do usuário quando ele entrar novamente no aplicativo, inclusive em outro dispositivo.
7. Garantir que um usuário não consiga acessar os dados de outros usuários.
8. Analisar como integrar a autenticação e o armazenamento na arquitetura atual do projeto, preservando as funcionalidades existentes.
9. Planejar a migração dos dados que já estão armazenados localmente no dispositivo para a nuvem.
10. Permitir que o usuário continue utilizando o aplicativo mesmo quando não houver conexão com a internet, respeitando as funcionalidades existentes.
11. Garantir que os dados armazenados na nuvem possam ser recuperados em caso de troca de dispositivo, desinstalação ou reinstalação do aplicativo.

# Comportamento esperado

## 1. Primeiro acesso ao aplicativo

Quando o usuário abrir o aplicativo pela primeira vez:

- Deverá poder entrar utilizando sua conta Google.
- O aplicativo deverá identificar o usuário autenticado.
- Deverá verificar se existem dados armazenados localmente.
- Deverá verificar se já existem dados associados à conta na nuvem.
- Caso existam dados locais e nenhum dado na nuvem, deverá planejar a migração dos dados locais para a conta autenticada.
- Caso existam dados na nuvem, deverá planejar como recuperá-los e combiná-los com os dados locais, quando necessário, sem causar perda de informações.
- Os dados deverão permanecer associados ao UID do usuário autenticado.

## 2. Acessos seguintes

Quando o usuário abrir o aplicativo novamente:

- Verificar se existe uma sessão autenticada.
- Recuperar os dados associados ao UID da conta.
- Sincronizar os dados locais e os dados da nuvem.
- Atualizar as informações quando houver alterações.
- Permitir que as funcionalidades existentes continuem funcionando.
- Evitar que dados sejam duplicados ou sobrescritos incorretamente.

## 3. Troca de dispositivo

Quando o usuário instalar o aplicativo em outro celular:

- Poderá entrar utilizando a mesma conta Google.
- O aplicativo deverá recuperar os dados armazenados na nuvem.
- As informações deverão aparecer novamente no aplicativo.
- O usuário não deverá depender do celular antigo para recuperar seus dados.
- As alterações realizadas no novo dispositivo deverão ser sincronizadas com a nuvem.

## 4. Troca de conta Google

Quando o usuário sair de uma conta e entrar com outra:

- O aplicativo deverá identificar corretamente a nova conta autenticada.
- Deverá carregar somente os dados associados ao UID da nova conta.
- Os dados locais da conta anterior não deverão ser apresentados ao novo usuário.
- O planejamento deverá definir como os dados locais serão protegidos, sincronizados ou isolados durante a troca de conta.
- Não deverá ocorrer transferência automática dos dados de uma conta para outra sem uma ação explícita e autorizada do usuário.

## 5. Funcionamento sem internet

O planejamento deverá considerar que o aplicativo já possui armazenamento local.

Deverá analisar como preservar o funcionamento offline e como sincronizar as alterações quando a conexão com a internet for restabelecida.

Também deverá considerar falhas durante o envio ou recebimento de dados, evitando perda de informações.

# Requisito fundamental: preservação e migração dos dados locais

O aplicativo já armazena informações localmente no dispositivo.

É necessário analisar como esses dados são persistidos atualmente e planejar uma estratégia segura de migração para a nuvem.

O planejamento deverá considerar:

1. Identificar todos os dados atualmente armazenados localmente.
2. Identificar os arquivos, bancos de dados, modelos e repositórios responsáveis pela persistência.
3. Identificar quais informações precisam ser sincronizadas com a nuvem.
4. Planejar como os dados locais serão associados ao UID da conta Google.
5. Planejar o envio dos dados locais existentes para o Firestore após o primeiro login.
6. Evitar que os dados locais sejam sobrescritos ou perdidos durante a migração.
7. Evitar duplicação de informações durante o processo de sincronização.
8. Garantir que os dados possam ser recuperados em outro dispositivo.
9. Planejar como tratar situações em que o usuário já possui dados na nuvem e também dados locais.
10. Definir uma estratégia para conflitos entre informações locais e informações armazenadas na nuvem.
11. Planejar como identificar se uma migração já foi concluída, evitando o envio repetido dos mesmos dados.
12. Garantir que os dados locais não sejam excluídos antes de confirmar que a migração foi concluída com segurança.

O planejamento deverá priorizar a integridade dos dados existentes e a recuperação segura das informações.

Não presumir que todos os dados do aplicativo já estão armazenados no mesmo local ou que todos podem ser migrados da mesma maneira.

# Tecnologias e serviços

Analisar e planejar a utilização das seguintes tecnologias:

## Firebase Authentication

Planejar a autenticação com conta Google, incluindo:

- Configuração do Firebase Authentication.
- Integração com o projeto Android.
- Identificação do usuário autenticado por UID.
- Persistência da sessão de autenticação.
- Tratamento de login, logout e falhas de autenticação.
- Recuperação da sessão ao abrir o aplicativo.

## Cloud Firestore

Planejar o armazenamento dos dados individuais dos usuários, incluindo:

- Estrutura de coleções e documentos.
- Organização dos dados por UID.
- Integração com os modelos e repositórios existentes.
- Operações de criação, leitura, atualização e exclusão.
- Sincronização entre os dados locais e a nuvem.
- Recuperação dos dados em outro dispositivo.
- Tratamento de falhas de conexão e sincronização.

## Firebase Security Rules

Planejar regras de segurança que garantam que:

- Cada usuário possa acessar somente os dados associados ao seu UID.
- Um usuário não possa consultar, modificar ou excluir dados de outro usuário.
- As operações de leitura e escrita sejam autorizadas.
- A estrutura dos dados seja protegida contra acessos indevidos.
- As regras sejam testadas antes da disponibilização da funcionalidade.

Não utilizar regras de segurança que permitam acesso irrestrito aos dados.
